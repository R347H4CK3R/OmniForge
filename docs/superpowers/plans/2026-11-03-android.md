# Android Companion Implementation Plan

> Execute inline under superpowers:executing-plans; autonomous execution approved by Chris.

**Goal:** Installable Android APK with Android-specific app tools and shared iOS maintenance.
**Architecture:** Native Kotlin frontend; llama.cpp JNI offline engine; shared Python services and JSON contract; signed GitHub release catalog.
**Tech Stack:** Kotlin 2.0.21, AGP 8.7.3, Gradle 8.9, SDK 35, NDK 27, llama.cpp b5046, Python stdlib.
**Spec:** docs/superpowers/specs/2026-11-03-android-design.md

## Global Constraints
One repository. Android 15 tablet supported. Keep App/ and iOS app identity. No public credentials. Stable Android signing key. Remote desktop and terminal full-screen landscape.

## Review Focus
Untrusted APK archive names/sizes; invalid/redirected URLs; catalog integrity and signing identity; missing host/model configuration; activity lifecycle and rotation/session preservation.

### Task 1: Shared contract and APK/host tools
- [ ] Write tests for archive traversal, bounded inventory and host build failures; run RED.
- [ ] Implement scripts/android_workbench.py and server Android API; run GREEN and full server suite.
- [ ] Add shared feature contract and maintainer instructions.

### Task 2: Native Android app
- [ ] Add Gradle configuration, manifest, native runtime, UI and workspace/model management.
- [ ] Add JVM policy tests; verify tests, lint and assemble in CI.
- [ ] Implement online/offline agent, APK inspection/import, host jobs, diagnostics and private remote screens.

### Task 3: Signed release and shared-change checks
- [ ] Add catalog validation tests, release generator, Android CI and dual platform checks.
- [ ] Provision stable signing identity in repository secrets without printing it.
- [ ] Build signed APK, inspect archive/signature and emulator launch.
- [ ] Publish APK/catalog and report exact checks and unverified device behavior.
